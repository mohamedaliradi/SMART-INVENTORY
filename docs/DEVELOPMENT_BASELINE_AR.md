# خط الأساس المعتمد لتطوير SMART INVENTORY

## قاعدة التطوير غير القابلة للتجاوز
هذا المستند يثبت أن الحزمة الأصلية الموجودة في:
`SMART_INVENTORY_RELEASE_CANDIDATE/SMART_INVENTORY_COMPLETE/`
هي المرجع الوظيفي والتصميمي الأساسي للمشروع.

**ممنوع حذف أو تعطيل أو تبسيط أي وظيفة موجودة في النسخة الأصلية.** أي تطوير لاحق يجب أن يكون إضافة أو إصلاحاً متوافقاً، مع الحفاظ على الواجهة العربية RTL وسير العمل الحالي. لا تُستبدل النسخة الكاملة بواجهة GitHub Pages/CSV المبسطة.

## الوظائف الواجب الحفاظ عليها
- تسجيل الدخول وحساب المدير والموظفين، وتفعيل/تعطيل الحسابات.
- إدارة عمليات الجرد للفرع أو المخزن، سواء بتحميل Excel/CSV أو بدء جرد مباشر.
- استيراد ملفات XLSX وCSV مع دعم أسماء الأعمدة العربية والإنجليزية للكود والاسم والرصيد والسعر والباركود.
- ملف أصناف رئيسي مستقل، والبحث بالكود والاسم والباركود.
- إدخال الأصناف بقارئ الباركود أو يدوياً، مع إمكانية إضافة صنف غير موجود.
- تسجيل تاريخ الصلاحية يدوياً والسعر والكمية، مع السماح بالكميات السالبة حيث يدعمها النظام.
- لوحة معلومات وإحصائيات الجرد والتقدم.
- تقارير الإجمالي والمجرد والعجز والزيادة والمطابقة وقيم الفروق، مع تصدير Excel.
- سجل النشاط وإقفال جلسة الجرد.
- العمل دون اتصال للحركات والبيانات التي تم تحميلها مسبقاً، وطابور محلي وإعادة المزامنة عند عودة الاتصال.
- منع تكرار الحركة عند إعادة الإرسال باستخدام معرف فريد لكل حركة.
- حفظ آخر العمليات والأصناف المحملة محلياً لدعم استكمال الجرد.
- واجهة عربية RTL قابلة للتثبيت كتطبيق PWA.
- أدوات Windows للإعداد والتشغيل، وإعادة تعيين كلمة مرور المدير، والنسخ الاحتياطي، واختبارات API.

## قواعد إضافة أي تطوير
1. لا تعدّل النسخة الأصلية مباشرة على `main`؛ التطوير يتم على فرع مستقل ومن خلال Pull Request للمراجعة.
2. لا تحذف ملفات أو شاشات أو حقول أو مسارات API أو صلاحيات أو اختبارات قائمة.
3. قبل أي تغيير وظيفي: احصر الوظائف الحالية واختباراتها، ثم أضف اختبارات حماية (regression) للوظائف المتأثرة.
4. بعد التغيير: شغّل الاختبارات ذات الصلة واختبارات الانحدار، ووثّق ما تم اختباره فعلياً وما لم يتم اختباره.
5. أي نقل لقاعدة البيانات أو ربط Google Sheets/Drive يجب ألا يفقد بيانات SQLite أو يغيّر تجربة المستخدم دون مسار ترحيل ونسخ احتياطي وتحقق من سلامة البيانات.
6. لا تُنشر تغييرات أو تُدمج في `main` تلقائياً. المراجعة والموافقة تسبقان الدمج والنشر.
7. لا تُدرج كلمات مرور أو مفاتيح أو بيانات حقيقية في المستودع أو سجلات الاختبارات.

## نقاط يجب التحقق منها قبل اعتماد إصدار
- مطابقة شاشات وحقول الواجهة الأصلية.
- صلاحيات المدير والموظف والمشرف/المشاهد إن كانت مطبقة.
- إنشاء الجرد والاستيراد والبحث والماسح الضوئي والإدخال اليدوي.
- الكميات السالبة وحساب العجز والزيادة والمطابقة والقيم المالية.
- الإقفال وسجل النشاط ومنع تكرار المزامنة.
- انقطاع الاتصال والعودة للمزامنة دون فقد أو تكرار.
- النسخ الاحتياطي والاستعادة.
- تشغيل Windows وPWA على الأجهزة المستهدفة.
- سلامة ترحيل البيانات عند تغيير محرك قاعدة البيانات.
