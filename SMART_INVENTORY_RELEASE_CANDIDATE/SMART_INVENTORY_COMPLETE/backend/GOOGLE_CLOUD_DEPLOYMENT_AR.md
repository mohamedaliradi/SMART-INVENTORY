# نشر SMART INVENTORY على Google Cloud — المرحلة الأولى

هذه ملفات تجهيز الحاوية فقط. **لا يعني وجودها أن التطبيق منشور أو أن قاعدة البيانات السحابية أُنشئت.**

## البنية المستهدفة

- Cloud Run لتشغيل واجهة FastAPI عبر HTTPS.
- Cloud SQL for PostgreSQL لقاعدة البيانات المركزية.
- Secret Manager لحفظ كلمة مرور قاعدة البيانات وأي أسرار تشغيل.
- Cloud Storage لحفظ النسخ الاحتياطية المؤتمتة.
- Google Drive يظل مناسباً لمشاركة ملفات Excel والتقارير يدوياً، وليس قاعدة البيانات الحية.

## ما تم تجهيزه في المستودع

- Dockerfile مبني على Python 3.12 ويشغّل Uvicorn على المنفذ الذي تحدده Cloud Run.
- .dockerignore يمنع إدخال ملفات البيئة وقواعد البيانات المحلية وملف إعداد المدير إلى صورة النشر.
- التطبيق الحالي في هذا المسار يستخدم psycopg وDATABASE_URL للاتصال بـ PostgreSQL، كما يحتوي على ملف المخطط الأساسي في migrations/001_initial_postgresql.sql.

## متطلبات قبل نشر بيانات حقيقية

1. مراجعة توافق جميع استعلامات التطبيق مع PostgreSQL واختبارها على قاعدة PostgreSQL فعلية.
2. إضافة مسار إعداد مدير أول آمن عبر Secret Manager/متغيرات بيئة، وعدم الاعتماد على admin_setup.json.
3. إكمال أداة ترحيل بيانات SQLite القديمة والتحقق من عدد السجلات وسلامة كلمات المرور والدفعات.
4. إضافة اختبارات API وتزامن ومزامنة Offline على PostgreSQL، ثم تشغيلها في CI.
5. إعداد Cloud SQL وCloud Run وSecret Manager وCloud Storage بصلاحيات IAM محدودة.
6. إعداد النسخ الاحتياطي والاستعادة وتجربة الاستعادة فعلياً قبل اعتماد التشغيل.
7. مراجعة إدارة الجلسات، وسياسات الوصول للفروع، وسجلات التدقيق، وحدود رفع الملفات.
8. إجراء اختبار قبول من أكثر من جهاز وفرع قبل نقل العمل الفعلي.

## إعداد Cloud Run / Cloud SQL (ينفذه مالك حساب Google Cloud)

1. افتح https://console.cloud.google.com/ واختر أو أنشئ مشروعاً، ثم اربط Billing.
2. أنشئ Cloud SQL PostgreSQL في منطقة قريبة من المستخدمين، واحتفظ باسم اتصال النسخة (Instance connection name).
3. أنشئ قاعدة بيانات ومستخدماً مخصصاً للتطبيق، بكلمة مرور قوية. لا تستخدم حساب postgres الفائق للتطبيق.
4. أنشئ Secret في Secret Manager لقيمة DATABASE_URL. عند استخدام Cloud SQL Unix socket تكون الصيغة العامة:
   postgresql://DB_USER:DB_PASSWORD@/DB_NAME?host=/cloudsql/PROJECT_ID:REGION:INSTANCE_ID
   استبدل القيم محلياً داخل Google Cloud فقط. لا ترسل كلمة المرور أو قيمة الاتصال السرية في المحادثة أو GitHub.
5. امنح هوية خدمة Cloud Run صلاحية الاتصال بقاعدة Cloud SQL وصلاحية قراءة السر المحدد فقط.
6. ابنِ الصورة من هذا المجلد (backend) وانشرها إلى Cloud Run مع ربط Cloud SQL وتمرير DATABASE_URL من Secret Manager.
7. لا تفتح الوصول العام للاستخدام الفعلي قبل إتمام اختبارات الأمان والوظائف والترحيل.

## أوامر البناء والنشر

بعد مراجعة الكود والاختبارات وإنشاء الموارد، يمكن تنفيذ البناء من مجلد backend:

    gcloud builds submit --tag REGION-docker.pkg.dev/PROJECT_ID/REPOSITORY/smart-inventory:TAG .

ثم النشر يحتاج تحديد Cloud SQL instance وSecret Manager وService Account وبيئة التشغيل. لا تستخدم أوامر نشر افتراضية قبل استبدال أسماء الموارد والتحقق من IAM.

## تنبيه التكاليف

Cloud Run قد يكون منخفض التكلفة عند الاستخدام المحدود، لكن Cloud SQL ووسائط التخزين والشبكة والنسخ الاحتياطي قد تترتب عليها رسوم مستمرة. راجع تقدير التكلفة داخل Google Cloud قبل إنشاء الموارد، ولا تفعل موارد مدفوعة قبل موافقتك على التكلفة.
